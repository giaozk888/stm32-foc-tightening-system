# SB2 电压矢量上限 0.8 → 1.6 V 单变量上板对照

## 结果

**控制验收 FAIL：起转后发生超速保护。** 单次 START，无自动重试。
相较此前0.8V完整周期中速度反馈接近零，本次编码器记录了明显角度变化和
两次速度上升，第二次上冲到60rpm保护边界。不能因此宣告1.6V已解决控制。

仅在新 `VoltageX2Trial` opt-in镜像把 `FOC_VOLTAGE_LIMIT_V` 改为1.60f；
默认/历史SB2仍为0.80f，历史BIN/ELF保留。积分仍限±0.75V，电流/速度PI
参数、速度电流输出限幅、采样/频率、判别器、CUR_CONFIRM、保护阈值、
原拧紧状态机与PWM pipeline未改。增加profile标识
`VLIMIT_MV=1600 ILIMIT_MV=750`，没有启用运行时可任意调限幅的接口。

发生于SPEED/RUNDOWN，目标20rpm。

- 滤波转速61.10266rpm；该次瞬时速度91.55273rpm。
- Iq指令已反向到-50.385mA；最近反馈Iq仍+60.234mA，Id=-20.017mA。
- 编码器valid=1，errors=0；这不是独立机械测速/相电流校准证明。

## 能推断与不能推断

1. 电压上限放宽后的单次结果支持“原0.8V限幅影响起转表现”的方向，但单次
   前后对照同时有零点/物理条件变化，不能证明它是此前不起转的唯一根因。
2. 明确的新现象是：速度突然上升，而电流指令从较高正值开始逐步卸载，
   瞬时转速先于20ms滤波转速上升。实际停止前才出现反向Iq需求，反馈仍正。
   这提示需要分析速度估计滞后、SB2积分卸载、电流实际反向响应与角度对应。
   不是单凭此表就认定某一个PI参数错，更不能提高超速阈值继续硬跑。
3. 本轮没有进入CONTACT_STOP/扭矩/保持阶段，不能声称完整流程通过。
4. 不应继续提高电压或同时扩大积分上限；这会混淆单变量试验且已有超速证据。

## 最终状态

故障后STOP/ANALOG SAFE均确认，SD/MOE/FOC关闭，Flash/SRAM保存，MCU停住。
用户确认12V关闭后，经既有bootloader mailbox仅恢复原B启动选择到generation661，
pending=none、attempts=0，停在B应用入口前，B应用未运行。最终SD=0、BDTR=0、
CCER=0。试运行/恢复期间应用和私有配置字节未变化，未再次START。
新的1.6V镜像仍保留A槽，未作为正常运行版本验收。
