## 动作是否生效

所有时间以下均相对板端本轮观察起点；没有制动器电气触发真值，不能把计划3秒或手动操作当作精确载荷时刻。

1. **2.090007s**，在RUNDOWN、有效RISING、负载均值27.87mA、有效确认30040us后，选定目标240→120rpm；切换前轨迹为240rpm/加速度0。
2. 后续记录速度依次经过约167.5、146.6、135.2、114.4、110.6、117.7、121.8rpm，之后逐渐回到约237rpm，证明实际降速和恢复动作发生。第2条恢复目标事件被3条容量覆盖，因此不能给出它精确时间/原因，也不补造连续目标曲线。
3. **5.815031s**，RISING且均值15.94mA、有效确认30043us后再次选择120rpm。
4. **6.070019s**，FSM进入CONTACT_CONFIRM，由于调度仅允许RUNDOWN而撤销降速、恢复原240rpm目标。该时刻原S曲线仍约209.003rpm、加速度约−200rpm/s；目标变化不等于实际速度瞬时跳到240rpm。

随后没有满足原250ms持续接触确认，退回RUNDOWN；最终CONTACT=0。
这不是成功拧紧，也不能据此断言是误接触：人工制动本来就可能满足低速＋高Iq的候选条件，且本轮没有固定工件真值。

## 当前判断

**负载调度与S曲线降速已实测生效。** 但不能宣称负载抑制或拧紧质量改善：只有一次手动制动，没有同条件OFF对照或可控制动力。
实测还明确暴露了“进入CONTACT_CONFIRM就取消降速并恢复240rpm”的边界，这可能不利于接触前减速，应在下一版单独处理，不能直接正式启用。
分类器本轮重置1次，从6.099964s重置到6.573000s趋势恢复约473.036ms，与目标调度切换是不同事件，不应混为同一个延迟。
