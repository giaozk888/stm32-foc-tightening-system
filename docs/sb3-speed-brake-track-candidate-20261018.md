# SB3 提前撤力与速度积分跟踪候选

## 范围与状态

针对1.6V实测中间歇起转后上冲至60rpm保护的问题，增加独立、默认OFF的
`SpeedBrakeTrackTrial`候选，继承`VoltageX2Trial`。本轮**只离线修改、构建和
验证**；没有连接调试器/串口、刷板、复位、改变B661启动选择或启动电机。

这是速度命令逻辑的修复候选，不是已完成真实电机稳定性验收。
新镜像标识`SPEED_CTRL=SB3 VLIMIT_MV=1600 ILIMIT_MV=750`，历史SB1/SB2
及0.8/1.6V对照BIN/ELF均保留，默认配置行为不变。

## 实测暴露的软件问题

故障记录：`tmp/voltage-x2-fsm-1792313964816534200.json`，对应1.6V SB2。

1. 约1190.911ms的帧：瞬时速度58.711rpm，20ms LPF速度25.526rpm，
   SB2的Iq指令仍为+211.78mA；高瞬时速度没有直接影响原速度PI撤力。
2. 约1205.910ms的帧：瞬时速度110.083rpm，滤波速度57.982rpm，
   Iq指令才降为-35.59mA，而板端Iq仍为+48.42mA。
3. 既有SB2从正向积分以10A/s卸载，一开始仍可能保留明显驱动需求。
   高速上升时，等待滤波速度和积分缓慢卸载会使制动请求偏晚。

这些是保存窗口中的命令与估计现象；尚未证明电机角度/相序、电流物理极性、
供电或实际反向制动能力全部正确。故障前窗口电压仅0.12–0.21V，
不能继续以“放大电压/积分上限”处理超速。

## 最小改动

新增 `firmware_common/speed_brake_track.h`：

- 原20ms滤波速度、速度PI Kp/Ki和SB2基本积分策略保持原样。
- 额外保存上一份**通过既有编码器有效性检查**的瞬时速度；不读取半更新DMA数据。
- 正向运行取连续两次瞬时速度较小者，反向对称处理；与已有滤波速度比较，
  只取更明确的同方向超调证据。单个瞬时尖峰不会启动这条提前制动路径。
- 达到原有5rpm超调边界和5rpm最小速度条件时，以原速度Kp乘以确认速度误差
  得到制动电流上限，不再容许旧正向积分顶住正向驱动。更强的既有制动不被减弱。
- 制动请求限制在原±0.4A输出范围内；不提高反向电流权限。
- 积分跟踪到`受限Iq指令 - 原滤波P项`，并保持原±0.35A积分限幅。
  没有保存/恢复旧大积分，没有额外转矩前馈。
- 无零点/编码器保护绕过。无效输入重置新历史，不让历史跨坏样本复用；
  原故障路径仍由原控制代码负责。

A/B `FOC_EncoderSpeedUpdate`中，在既有PI反饱和/积分提交之后，且仅在
`MOTOR_MODE_SPEED`内应用新上限。这会改变SPEED制动策略，不应说“所有
控制算法完全未改”。没有改20kHz FOC数学、PI参数、SVPWM或其他模式控制。
最终Iq仅在限幅处理完成后发布一次，避免ADC在两次写指令之间抢占，读到
尚未经过快速制动上限的临时正向命令。

`FOC_ResetController`、模式转换、非SPEED采样以及不合理编码器跳变时清空
新速度历史。零参考与方向反转也清空；无静态保存的转矩或积分可在STOP后恢复。
新增状态只有8B；没有heap、printf、UART或20kHz ISR插桩。

## 真实故障输入回放

`tools/replay_voltage_x2_braking.py`只读精确Flash/SRAM和匹配ELF，校验镜像
哈希、故障标志、停机状态及环形记录格式。专项测试执行真实SB2/SB3 C函数，
对同一保存速度输入进行逐帧比较。

在现有32帧窗口中，用第一帧初始化历史后，新分支最早在1177.873ms触发：

| 项目 | 保存/回放值 |
|---|---:|
| 该帧滤波速度 | 11.6166rpm |
| 该帧瞬时速度 | 36.6211rpm |
| 原SB2 Iq请求 | +262.850mA |
| SB3同输入回放Iq请求 | -16.904mA |
| 跟踪后的速度积分 | -42.054mA |

到窗口最后一帧，SB2请求约-50.38mA，SB3同输入回放请求约-254.01mA，
未超过原电流权限。真实SB2的保存输出可由同一旧C策略复现。
该限幅优先撤销错误方向的驱动需求，允许Iq请求在确认超调时发生阶跃；
本例约从+263mA切到-17mA。它不是全工况平滑控制，也不证明实际相电流
能够立即反向。是否抖动、反向过冲或母线回馈异常均须实机检查。

**重要：这不是电机仿真。**更早改变Iq后，真实角度/速度输入也会改变。
回放只证明命令策略更早撤力并跟踪积分，不能预测实机峰值，也不能证明
将不再触发60rpm或不会出现反向过冲/抖动。现有窗口之前的首次制动时刻未知。

## 冻结的部分

- 1.6V矢量限幅、±0.75V电流积分限幅不再扩大。
- 电流判别器、CUR_CONFIRM、hard overcurrent、60rpm故障阈值不变。
- one-cycle PWM、入口真实CCR commit、采样频率/相位、IRQ优先级不变。
- 原拧紧状态机、接触条件、各扭矩阶段配方不变。
- 位置环、IQ直控、电气零点、方向、极对数、CAN/Pigweed/IAP不变。
- A/B启动与回退逻辑不变；未增加自动START或故障自动清除。

预处理后的完整函数比较确认FOC_CurrentLoopStep、PWM入口/生成、ADC处理、
ProtectedLoop_Pair、current validator、FocFp_Poll和TighteningTask逐字一致。
实际`foc_adc_timing_stm32.c.obj`与此前1.6V版逐字节一致。

## 下一步边界

需要人工上板预检SB3零点和时序，再在明确现场条件下做一次低能量空载速度
响应验证；不能直接把“更早发了反向Iq”当作实际制动已经建立。
特别需要关注电流反向响应、反向过冲、速度保持和停止。
现有空载接触误分类与初始间歇起转仍未获得物理根因的唯一解释。
本轮到离线候选完成即停止，不自动刷板或启动电机。
