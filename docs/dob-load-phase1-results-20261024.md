# DOB负载自适应第1阶段：实现与10次重复结果

结论：只读负载特征/分类已接入现有Simulink，13场景每组10个固定种子，分类OFF/ON各10次，共130对、260次仿真。仅软件验证，尚未接入速度、工作Iq上限、DOB增益或FSM决策，不表示真实电机或真实拧紧性能已验证。

## 实现

- `simulation/dob_simulink/native/load_features.{h,c}`：无控制器/HAL依赖的纯C特征及分类。输出有符号/方向归一化负载[A等效]、趋势[A/s]、有效覆盖率、驻留、质量与分类。
- `native/load_features_sfun.c`：单独DWork状态及同时间求值缓存，输出只接日志。
- `build_load_phase1.m`、`phase1_config.m`、`phase1_inputs.m`、`phase1_metrics.m`、`run_load_phase1.m`：复用原C控制/DOB及机械模型、实测短窗的两个假设，生成配对结果、CSV及曲线。
- `tools/report_dob_load_phase1.py`：独立逐帧审计及中文汇总；`tests/load_features_host.c`、两份Python回归覆盖核心及审计器故意注错。

阈值在正式运行前固定：100ms窗口、跨度至少60ms、有效覆盖率60%、30ms有效驻留，20ms可信数据缺口后UNKNOWN。分级10/25mA、迟滞5mA，趋势±20mA/s。这些是可配置的软件起始值，未作真实负载标定。

只接受原DOB有效、LPF实际更新、新鲜且来源时间戳推进的帧。可疑点不进入特征统计，不提供驻留时间；短缺口保留记忆但当前标签无效，长缺口仅清空分类层，不调用底层DOB Reset。

## 实际验证

- C核心在-O0/-O2下回归通过；Python分类/审计6项、原Simulink环境5项，共11项通过。
- GCC主机DLL、MSVC MEX和Simulink模型实际构建、运行完成。
- 独立检查910130个对应采样帧：原控制、观察器、噪声输入和机械真值完全一致；没有控制出口、补偿增益或原算法参数变化。
- 129565个不可用分类帧的信用、均值、趋势、驻留规则检查通过；10个单点+700mA均未污染原DOB LPF或新特征，没有额外底层硬复位。
- 全部有限数、原总Iq限幅及软件数值守卫检查通过；283个冻结源文件哈希一致。A/B固件、独立安全限幅及物理板程序未修改，没有硬件连接或烧录。
- 无载/无载尖峰误报HIGH不超过1%，正向持续阶跃/卸载/反向阶跃HIGH检测800ms内的五项预声明合成检查全部通过。此处只代表这些合成检查，不是所有场景已可用于闭环调度。

## 未解决项及下一步

1. 实测回放标签仍有抖动：7秒仿真中，测量假设转换25.5±4.95次，电流脉冲假设37.2±9.35次；典型合成卸载场景只有5次。有效率不是准确率，不能据94%就开始自动调参。
2. 当前标签将幅值和趋势合在同一枚举，RISING/RELEASING优先于HIGH。高负载期间的HIGH标签召回在两种实测假设中分别为55.1±10.8%与22.5±16.6%（9个确有≥25mA真值的试次）。这包含趋势标签竞争和噪声影响，不等同于DOB负载估计完全丢失。下一轮先考虑幅值等级与趋势分开输出，并评估迟滞/驻留，而不改PI或电机保护。
3. 原monitor遇到来源无效/时间/序号/饱和异常会直接复位。3ms来源无效场景中，原DOB发生3次真实Reset，分类连续不可用493ms；30ms来源无效或电压饱和场景中，原Reset为30次，分类不可用520ms。与仅隔离单尖峰的2ms缺口不同。新分类层每个长缺口只清空一次，本轮没有为了提升有效率修改原门控。
4. 五次实机短窗的尖峰成因没有独立真值。测量噪声/真实电流脉冲两种假设都必须保留，软件分类阈值尚未通过真实负载标定。

第1阶段的实现及软件对照已完成；进入第2阶段前，应先提高实测回放标签稳定性、明确上游来源失效回退，并处理主动降速导致误CONTACT的规则。当前没有启用任何自适应控制出口。
