# DQ OFF/ON各三次固定批次

用户明确要求各三次取平均，随后确认12V关闭、现场条件不变、能全程在场。
只使用原运行镜像，固定OFF/ON交替6轮，不增加电流档位、反号或自动重试。

用户关闭12V后先恢复B928，回执：
`tmp/dq-fsm-restore-1792584600340137700.json`，PASS。
保持原确认B payload/boot/private，不执行B应用。

新增主机脚本 `tools/dq_repeat_batch.py`：

- 默认只验证文件，不连接硬件。
- 准备入口要求12V关闭及空载固定/解锁确认；执行入口另要求上电无报警、
  限流0.5A、操作者全程在场。
- 严格6轮 `OFF, ON, OFF, ON, OFF, ON`；没有故障补跑或额外START。
- 第一轮沿用原bootloader A试运行/正常健康确认；后续仅在完整记录证明上一轮
  自然空载超时、输出关闭/CPU停住、没有独立保护时，才复位已确认A。
- 每轮都重新零点校准、独立健康/时序/配方预检，然后才执行原START。
- 后续复位不写mailbox、不刷固件、不改IRQ/控制参数/期限，不运行B应用。
- 每轮原8秒RUNDOWN及12秒lease保留，自然超时是空载采集结果而非拧紧成功。
- 不合格速度跟踪保留作质量数据；独立保护、deadline miss/CCR late、
  反馈/关断/记录证据缺失会停止整组，不以均值隐藏失败轮。
- 每轮保存独立JSON、完整Flash/SRAM和tokenized日志。最后输出OFF/ON的
  mean、sample SD、min/max、有效数量/缺失数量及ON-OFF均值差。
- 启动、加/匀速误差、超调、settling、Iq命令/测量峰值、积分器峰值、
  FOC/实际CCR余量均保留单位；没有settling/起转值时不拿零代替。

测试：15项主机/原镜像测试通过，覆盖恰好6轮、固定顺序、保护失败不能进入下一轮、
质量失败不丢弃、缺失值不填零、均值/SD、默认不接设备及现场条件门控。

准备记录：

```
python tools/dq_repeat_batch.py --prepare-off --baseline-restore tmp/dq-fsm-restore-1792584600340137700.json --drive-off-unlocked-no-load-fixed
```

人工再次确认上电无报警并全程在场后执行：

```
python tools/dq_repeat_batch.py --execute-six tmp/dq-repeat-stage-1792584803129340900.json --operator-present-whole-batch-drive-on-no-alarm-05a
```

平均值只是n=3/组的描述性结果，不等于统计因果、真实扭矩或带工件拧紧验收。
顺序交替降低单方向时间漂移，但温升/初始转子角未严格受控；零点照实保留。
组末输出关闭并停住后提示关闭12V，再按最后一轮回执恢复B启动选择。
