# dq 解耦一次性离线收尾

本轮仅完成文件审查、真实历史数据复算、原 C 数学/量化代码的主机运行、
四种符号构建复核和回归测试。没有连接板卡、烧录、复位、修改启动选择或启动电机。
没有修改控制算法、参数或保护阈值，也没有修改正式 B。

## 结论分级

| 检查项 | 当前结论 | 证据边界 |
|---|---|---|
| Park 与解耦符号 | 当前 `d:-we Lq Iq / q:+we Ld Id` 一致 | 软件约定；不能代替硬件相序/磁链零点验证 |
| we 单位和极对数 | signed electrical rad/s，10 极对只乘一次 | 已审查真实编码器速度/角度来源 |
| Ld/Lq 单位 | 20.03e-6 / 11.18e-6 H | 数值仍为未正式合格的候选辨识值 |
| 电压合成/限幅/AW | PI 与补偿先相加，再统一矢量限幅，饱和跟踪扣回 FF | 原计算顺序与积分限幅未改 |
| FOC 超时/CCR late 导致延迟 | 旧两轮均无证据支持 | 两轮 deadline miss/actual CCR late 均为 0；不代表新插桩无需重测 |
| PWM 共模平移造成两轮差异 | 旧两轮均未发生平移或规划拒绝 | 全局计数 adjusted=0/rejected=0，不等于已测实际相电压 |
| 349 ms 才第一次动 | **不是这个指标的含义** | 旧数据已记录约 142 ms 时位置变化 0.68° |
| 启动恶化的唯一物理根因 | **仍未定案** | 缺第一 500 ms 的同帧电压、严格一致初始条件和重复对照 |

不能把“代码没有明显错误”写成“已证明参数/电角零点/硬件映射全部正确”，
也不能把一次 ON/OFF 差异写成确定的因果关系。

## 1. 起转指标究竟是什么

原 `SpeedFriction_Observe` 不观察首次机械运动，而是要求：

```
speed_ref 沿命令方向超过 2 rpm
且 filtered speed 沿命令方向达到 2 rpm
连续维持 50 ms
```

中途跌回条件以下，连续计时归零。记录的是该次成功连续窗口的起点。

| 旧记录 | 首个已观察到 | 同一轮的原起转指标 |
|---|---|---|
| OFF | 主机 STATUS 155.62 ms，位置 0.79°、控制速度 1.5 rpm | 174 ms |
| ON | 主机 STATUS 142.21 ms，位置 0.68°、控制速度 1.3 rpm | 349 ms |

上述首个位置观察以 |POS|>=0.1° 作**离线展示条件**，没有写入控制器/保护。
稀疏观察只说明“此前已经有位移”，不是精确起动时刻或外部测量。
ON 达到持续低速运动条件更晚，不能改写成“349 ms 之前完全不动”。
加速平均误差 7.41→10.47 rpm 的恶化仍是原统计事实，没有删改。

旧 FRC 的 R/C/I 三行已按同一个 task seq 连接，保留整个窗口，不能把
监控打印周期约 100 ms 当成连续 1 kHz/20 kHz 波形；也不能把这些值强行
与另一 seq 的 DQ 电压查询合并。完整数据见下述 JSON，不靠挑选个别点定论。

## 2. 一计数零点差有多大

真实配置 3300 mV / 4095 counts / 120 mV/A：

```
1 ADC count = 6.71551 mA（单相）
仅 U 零点变化 1 count：Clarke/Park 电流偏移向量模长约 7.75440 mA
```

OFF 零点 U/V=1559/1563；ON=1560/1563。不是严格相同的电流测量条件。
在“前一拍积分器相同、未饱和”的单次 PI 更新中，这个偏移对应的最坏
瞬时 PI 电压差尺度约为 d 轴 0.863 mV、q 轴 0.733 mV，已与观察到的
数百微伏解耦项相当。该计算**不是**长期积分漂移预测，也不能单独解释
175 ms 的差异；偏移方向随电角度变化。

编码器 16384 count/rev：1 count=0.0219727°。若以标称 1 ms 差分估计，
单 count 的瞬时机械转速尺度为 3.662 rpm（实际代码使用真实 dt 并低通）。
所以低速持续达标指标与“有没有发生过小位移”本来就不同。

本轮没有统一/手工覆盖校准零点，更没有修改零点准入或电流判别阈值。

## 3. 补偿量与 PWM 整数分辨率

原中心对齐 TIM1 ARR=4249，原 duty→CCR 代码使用 ARR+1=4250。
按配置母线 12 V，1 tick 的命令换算尺度为 2.82353 mV；理想硬件平均极电压
的近似尺度为 12/4249=2.82419 mV。不是对实际母线/死区/桥输出电压的测量。

旧 ON 电压观察中 d 补偿 -609…-115 uV，q 补偿 -198…+405 uV，小于一个
CCR 量化步进。但小于一步不等于永远不起作用：是否跨整数边界与原 duty
的小数部分、电角度和三相关系有关。

为检查这一点，主机工具取出**原逆 Park/SVPWM 算术**，链接原
`foc_fast_trig.c`、`foc_pwm_common_mode.c`、`foc_adc_window.c`。
冻结每个已保存电压帧的 PI 值，在主机内取 720 个假设角度比较加补偿前后。
这不是实机扫角/新辨识/电机模型仿真，没有向输出端发送任何命令。

| 主机量化对照 | OFF 15帧×720角度 | ON 15帧×720角度 |
|---|---:|---:|
| 有效假设组合 | 10800 | 10800 |
| 规划拒绝 | 0 | 0 |
| CCR 有变化的组合 | 0 | 2773 |
| 单相 CCR 最大变化 | 0 | 1 tick |
| 线间 CCR 差最大变化 | 0 | 2 ticks |

ON 的 25.68% 是**均匀假设角度网格**的比例，不是电机实际运行中改变 CCR
的比例。实际角度没有保存在旧电压查询帧中，无法还原这个比例。
更不能把冻结 PI 的单帧对照解释成整个闭环速度响应。

结论只到：补偿项在当前整数 PWM 尺度下较小且呈离散作用；初始零点、
转子位置、摩擦/齿槽、测量噪声都是需要控制的混杂项。未证明哪一项是
这次启动/加速差异的主因。不能据此调大补偿、改 PI 或反相序。

## 4. 取证工具问题也已收尾

- 修复真实 Pigweed ARM 字典的 `■msg♦...■module♦...` 元数据直接贴着
  最后一个数值时，Python 把模块/文件名误读成浮点值的问题。
- 用实际 ARM ELF 字典对四行压缩日志编解码后再交给报告器，验证全部字段。
- 同一个 seq 若出现互相矛盾的重复行，拒绝混合，防止跨复位或不同抓取
  拼出伪同帧；完全相同的重复行可去重，不完整帧不当作完整证据。
- 旧日志第一 500 ms 的电压仍然输出未知，不补造零值。
- 精确最终 full-rate 统计仍需相同停机快照的完整 SRAM/Flash/VTOR/ELF。

这些修复只影响离线取证，不影响 MCU 控制结果。
