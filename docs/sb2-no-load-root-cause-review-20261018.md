## 已确认的两层问题

### 1. 电流执行/反馈已跟不上，电流 PI 电压指令接近限幅

完整流程保持段最后 32 帧跨越停机，剔除最后 3 帧零指令后：

| 保留窗口约 2.721898–2.749855 s | 结果 |
|---|---:|
| 有效保持帧 | 29 帧，约 28 ms 时间跨度 |
| Iq 指令均值 | 150.000 mA |
| Iq 板端反馈均值 | 49.609 mA |
| Iq 误差均值 | 100.391 mA |
| Id 板端反馈均值，目标为 0 | 39.324 mA |
| Vd / Vq 指令均值 | -0.361030 / +0.712277 V |
| 电压矢量模长范围 | 0.792477–0.800000 V |
| 触及 0.8 V 上限，容差 10 µV | 17 / 29 帧 |
| 超过上限 99% | 29 / 29 帧 |
| d / q 积分项最大绝对值 | 0.363177 / 0.708694 V |
| 保存输出相对 `V = I_term + 0.080*error` 最大残差 | 2.86e-8 V |

源码 `main.c` 的 `FOC_VOLTAGE_LIMIT_V=0.80`，独立积分限幅为 0.75 V。
本窗口首先体现为**矢量电压饱和/近饱和**，不能混称为积分项顶到 0.75 V。
现有 vector tracking anti-windup 会把积分拉回饱和指令一致值。
保存值与其 P+I 输出关系吻合，未呈现这个窗口里 PI 被停算或积分突然清零。

短测记录结束前只有 2 帧仍为非零大电流指令，均约 0.398 A 指令、
约 0.092 A 的 Iq 反馈，电压矢量都为约 0.8 V。该窗口太短，不能替代
整段起转数据；但它与完整流程尾部的“接近电压上限、仍有明显反馈误差”一致。

重要边界：以上 Vd/Vq 是软件指令，dq 电流是板端 ADC/角度模型计算结果。
既没有独立实测相电流，也没有证明桥输出端实际施加了相同电压。
因此 0.8 V 限幅参与了软件饱和，是**确定现象**；它是否是物理不起转
的唯一原因，仍未确定。不能以此直接提高限幅、电流或 PI 增益。

### 2. 原“接触→完成”只证明条件和时序满足，不证明真实转动/拧紧

`TighteningTask` 的现有接触条件为：

- 检测转速绝对值不大于 10 rpm；
- 驱动 Iq **需求**不小于 0.30 A；
- 上述条件连续满足 250 ms。

它没有要求之前必须成功起转，也没有独立的物理接触或扭矩测量。
本次需求持续上升但速度接近零，约 0.933 s 观察到 CONTACT_STOP。
后续 80/100/120/150 mA 与 HOLD 按既有时长运行，于约 2.865 s 返回 OK。
因此空载状态机可以完整 PASS，同时仍未达到 20 rpm、未证明电流跟踪。
这不是 host 提前发 STOP 导致的：本轮 host 确实观察了全部阶段及 DONE OK。

## 已排除或收窄的方向

- 本轮不是 50 µs deadline 或 CCR late 导致停机：29.3412 µs、miss=0、late=0，
  最小 margin=15.1412 µs。
- 没有触发 CUR_CONFIRM/current protection 的故障锁存：86/86/0，首故障 valid=0。
  这不等于物理反馈链已被独立校准。
- 活跃路径不是历史 Median/Trend 插值：当前 FAST_CURRENT_REJECT 使用合格的
  **本对原码**换算电流；可疑对冻结 PI，不把幅值统一除以 3。
- 软件生成 pending 54661 次，FOC 计算计数 196117，真实 CCR 提交 195218 次。
  这些累计数含启动/READY，不能全部当作带功率运行次数；但也不是整轮从未计算
  或未写 CCR。软件提交计数并不证明六根线之后的功率桥实际动作。
- IU/IV 的软件通道为 ADC1 IN1/PA0、ADC2 IN2/PA1；默认 `(zero-raw)`，
  未在本轮交换 U/V 或翻转符号。电气零点10507、极对数10、编码器方向-1未变。

  推导为必须反转整个 FOC 反馈。

## 暂不能排除的物理原因及需要的证据

| 方向 | 当前证据能否确定 | 最有区分度的下一份证据 |
|---|---|---|
| 0.8 V 是否不足以克服实际驱动死区/压降 | 只能确认软件已接近上限 | 同周期电流误差、限幅状态与实际桥输出/相电流 |
| 驱动桥、控制信号、U/V/W 连接 | 软件 gates/CCR 正常不等于端子输出正常 | 在已确认条件下核对桥输出与实际相电流，而非只看 MCU 引脚 |
| IU/IV 对应、符号、实物增益、采样恢复 | 标称增益一致；实物未独立验证 | 已知方向/幅值输入下的相电流对照与 ADC 原码 |
| 电气零点/编码器/相序对应 | 参数固定不代表物理对应已校准 | 定向测试或独立转子/相序对应证据 |
| 供电跌落或进入限流 | 只有设定和低频板端值 | 与启动同步的母线和电源限流状态 |

停机后的 PC4=570，boot VDDA=3285mV，按原比例换算约11.43V；
这是板端低频估值，不是起转瞬间的独立电源测量，不能排除瞬间跌落。
TIM1 deadtime配置为85个170MHz时钟、约0.5µs；未补偿并不自动证明它是主因。
也不能只因 PI 饱和就把锅全部归于电压限幅。

优先顺序应是保存**起转阶段**电流/电压/限幅及门控上下文并验证实际反馈/输出链，
再决定是否更改驱动参数。现有32帧环只留下结束前窗口，缺少完整早期电流跟踪。
状态机后续可考虑区分“未成功起转”和“真实接触”，但那是另一个修改任务；
本次没有据此改条件或跳过任何保护。
