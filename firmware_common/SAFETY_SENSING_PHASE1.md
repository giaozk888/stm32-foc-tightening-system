# 可信采样与安全联锁：第一阶段软件实现

日期：2026-09-30。状态：独立锁定诊断固件 + 上位机离线验证；未部署、未刷写、未复位、未试转。

## 先说边界

这是为后续标定和硬件联锁验收准备的工程诊断版本，不是已验收的安全控制器。

- 新增 `SafetyLocked` 构建预设；正常 `Debug` / `Release` 的启动流程没有被替换。板上现有固件仍是原行为，不能因为本地代码完成就认为实机已锁定。
- 原正常启动流程会为了运行零点校准使能桥并启动 PWM；“不发 START”不能代替功率物理隔离。
- 锁定版不运行电机、拧紧、通用命令、Router、BootHealth、Pigweed 日志/RPC/KVS任务，也不做运行电流零点校准。
- 软件持续要求 SD 低、TIM1 MOE 关闭、FOC 禁用并停止 PWM。这是输出命令/MCU寄存器观测，不是独立功率级回读，更不能证明故障功率管已经断电。
- 不存在解除锁定命令。联锁数据只用于显示缺项，不能授权运动。
- 实体急停、独立使能/关断回读、真实电流/母线/温度标定、编码器验收和断链保护尚未完成。没有随意指定尚未核对的接线或急停 GPIO。

## 固件如何运行

`foc2_app_a` 与 `foc2_app_b` 的 `StartupTask` 在任何正常启桥/校准/任务创建前，进入共享的 `safety_locked_boot.inc` 不返回循环。`PowerStage_Enable` 在此构建下也只关断后返回。构建要求 CAN 遥测与拒绝控制回复开启，禁止同时开启链路探针、日志流、shadow 诊断。

锁定循环约每 100 ms：

1. 要求 SD/MOE/FOC 关闭；不启动 PWM、注入 ADC 或运动任务。
2. 只执行 ADC2 硬件校准和常规转换。分别读取 PC4（ADC2 CH5）、PC5（ADC2 CH11）的三次原码。
3. 保留原始三元组，不用中位数掩盖离散采样；转换失败不更新时间、不用旧值冒充新值。
4. 评估采样质量、未验收联锁和故障锁存；调用已有 CAN 有限恢复服务。
5. 发布只读状态/质量/原码，UART 每秒输出诊断摘要。UART 不开启通用命令解析。

锁定版改为独立ADC模式、统一247.5周期采样，转换前后停止常规ADC，超时也尝试停止，避免一次转换异常后永久卡在BUSY。正常FOC采样助手不作修改，因为它不能随意停止已运行的注入采样。上述模拟电路采样时间是否足够仍需实测，不以更长采样时间直接宣称问题解决。

在锁定版，0x181 角度/电流、0x182 母线/转速均明确标为无效；原有 0x180/181/182 数据格式不变。不把诊断原码自动换算为可信 V/A/℃。Pigweed 的应用级全局对象在此构建中也被排除，避免仅因 C++ 全局构造而保留 RPC/KVS 写 Flash 路径。正常版日志功能不受影响。

采集失败、原码越界、三次不一致、过期、CAN 恢复耗尽或观测到 SD/MOE 异常置本次启动的故障锁存；新读数恢复或 CAN 自动恢复不能解除锁定。状态帧故障码 8 表示锁定诊断异常，不用于正常版零点校准故障码。

## 采样质量

共享 C 模块：`safety_guard.h/.c`，可脱离 HAL/FreeRTOS 进行主机测试。

| 位 | 含义 | 当前策略 |
| --- | --- | --- |
| 0x01 | 未标定验收 | 当前固定为未验收，稳定也不会清除 |
| 0x02 | 采集失败/未取得完整三元组 | HAL 失败、空输入、不完整组均不可用 |
| 0x04 | 原码越界/策略非法 | 12 bit 原码范围 0..4095；不是物理安全阈值 |
| 0x08 | 三采样不一致 | 最大值减最小值 >60 原码；仅诊断阈值 |
| 0x10 | 过期 | 无成功采样或距最后成功采样 >500 ms |

失败不会刷新成功时间；失败计数和不一致计数饱和而不回绕。时钟允许 uint32 tick 正常回绕，未来时间按过期处理。0V 可对应正常原码，因此不能仅凭原码为零判断断线；恒定值也不能排除卡死。完整开短路/卡死诊断需结合实际模拟电路、受控输入和独立参照。

## CAN 诊断协议

500 kbit/s，标准数据帧，DLC=8，uint16 字段小端。新增 ID 不与旧遥测/日志协议冲突。

| ID | 字节布局 |
| --- | --- |
| 0x184 | `[version=1, flags, 缺项lo, 缺项hi, PC4质量, PC5质量, seqlo, seqhi]` |
| 0x185 | `[PC4原码0lo/hi, 原码1lo/hi, 原码2lo/hi, seqlo/hi]` |
| 0x186 | `[PC5原码0lo/hi, 原码1lo/hi, 原码2lo/hi, seqlo/hi]` |

`flags`：bit0 永远表示锁定，bit1 表示 ADC2 初始化/校准成功，不代表标定验收。编码器强制补上启动锁定位；采集未准备好则补采集失败，质量异常强制带相应母线/温度缺项。失败组原码为三个 `0xffff`，不能作为真实 ADC 值。

缺项掩码：bit0 启动锁定，bit1 实体急停，bit2 独立功率回读，bit3 电流标定，bit4 母线标定，bit5 温度标定，bit6 编码器，bit7 端到端链路，bit8 固件确认，bit9 配方验收，bit10 故障锁存。

未实现的验证适配器始终 false。不把 CAN 控制器 ready 当成端到端链路验收，不把 SD 输出低当成独立回读。固件确认只读取现有 BootMeta，不写入、不自动确认 trial。序号标识采样/发送尝试组，不保证所有三帧成功送达；队列满会出现缺组。

## 上位机

- “链路诊断”显示启动锁定、各项缺失原因、PC4/PC5质量和三次原码。
- 只接受指定版本、标准数据帧、8字节、已锁定标志、已知质量位与一致缺项掩码；畸形帧不刷新数据。
- 质量与原码都要求新鲜（≤500ms）、序号前进。原码只和相同序号的新鲜质量报告配对；缺帧/不同组显示“等待同序号原码”，不拼接旧值。
- 过期明确提示“不授予运动权限”；旧固件没有 0x184 时明确显示未验收，不假装通信失败或已验收。
- 控制流程增加“采样标定/保护未验收”锁定项，默认 false。上位机仍不发送运动命令；0x184 永远不能让 START 解锁。
- 实屏触控/Qt5/DRM 尚未在本轮验证；Windows离线预览与界面测试使用合成数据，不是实机测量。

## 构建与验证（不含部署）

在 `foc2_app_a` 和 `foc2_app_b` 分别运行：

```powershell
cmake --preset SafetyLocked
cmake --build --preset SafetyLocked -j 6
```

产物位于各自 `build/SafetyLocked/foc2.elf/.hex/.bin`；A向量地址0x08008000，B向量地址0x08040000，单槽224KiB。

从项目根目录运行主机测试：

```powershell
cmake -S tests/safety_guard_host -B tests/safety_guard_host/build -G Ninja -DCMAKE_C_COMPILER=D:/Qt/Tools/mingw1310_64/bin/gcc.exe
cmake --build tests/safety_guard_host/build
ctest --test-dir tests/safety_guard_host/build --output-on-failure
cmake --build lubancat_hmi/build_win -j 6
ctest --test-dir lubancat_hmi/build_win --output-on-failure
powershell -NoProfile -File tests/safety_guard_host/verify_locked_image.ps1
```

HMI首次配置需设置 `HMI_BUILD_TESTS=ON` 并提供本机Qt路径。`build_win` 为Windows构建，不可复制其exe到鲁班猫运行。静态审计检查预设、向量/镜像长度和禁用入口未链接；它不能证明实际 GPIO 关断或硬件安全。

测试包括：采集失败不刷新、500/501ms边界、tick回绕、尖峰和“中位数看似正常”的不一致组、非法原码/策略、计数饱和、256组模拟联锁证据组合、CAN帧/序号/过期/配对、旧固件等待状态、缺项/原码显示、控制锁定和1024×600布局。日志筛选、快照、趋势等原有测试一起回归。

本轮验证结果：主机采样/联锁测试1/1、HMI回归12/12通过；正常A/B另建 `build/SafetyCompatibility`，开启CAN日志与拒绝控制回复后编译通过，镜像154480/153592字节。锁定A/B编译及静态审计通过；互斥CAN日志流、不启用拒绝控制回复两个非法配置均被CMake拒绝。锁定版大小与SHA256以审计脚本当次输出为准。

## 部署限制与下一阶段

本轮未连接板子执行任何变更。锁定版不是日常运行版，也不提供运动、正常Pigweed日志或固件升级命令。

尤其不要把锁定诊断版通过正常IAP部署后手动强制确认：它不运行 BootHealthTask，因此试运行不自动确认，下一次启动会遵循现有Bootloader的回滚策略。应先制定并验证隔离现场下的诊断加载/恢复方案，保留原已验收镜像与BootMeta；本轮没有擦除或修改它们。

后续顺序：

1. 核对板级电路、分压、电流传感/运放、温度传感器和ADC参考/采样时间；按受控输入采集原码与独立仪表参照，确定量程、误差、滤波、开短路/卡死判据。
2. 设计独立于Linux、CAN、普通应用任务的硬件急停/使能关断链路与反馈，核对极性、掉电默认态、上电瞬态。没有硬件验收前持续锁定。
3. 隔离功率/机械风险后，验证锁定版上电/复位不启桥、采样报告、断链/坏帧/故障锁存和恢复不自动启机。故障注入不能靠离线测试冒充完成。
4. 基于已验收的硬件、标定和保护时限，把锁定门控纳入实际启动、校准和每条运动入口。执行端独立复核命令、工况与故障；上位机显示不能作为安全许可。
5. 通过有记录的停机时限、急停、反馈不一致、传感异常、断电重启、断链重连测试后，才讨论正式控制解锁。

安全响应时限、阈值和复位条件必须由硬件风险与实际系统验证决定，本阶段没有宣称满足工业安全等级或认证。
