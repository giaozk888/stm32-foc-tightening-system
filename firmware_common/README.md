# STM32 → LubanCat 只读 CAN 帧 v1

2026-10-08 本地新增独立 `foc.MotorControl` RPC 服务和共用 UART 作业入口：
[`MOTOR_CONTROL_RPC_20261008.md`](MOTOR_CONTROL_RPC_20261008.md)。当前仅完成离线实现；
生产板端永久拒绝远程 Arm/Start/Stop，HMI 只查询状态，没有刷写或部署，不能据此控制电机。

2026-10-02 本地 C++ 参数模块化及 main 入口清理记录：
[`CPP_MODULARIZATION.md`](CPP_MODULARIZATION.md)（未刷写，不改变控制权限）。

当前设备已确认的 APP B 发送标准 11-bit ID `0x180`、`0x181`、`0x182`
经典 CAN、500 kbit/s 帧；2026-09-29 鲁班猫实收并经 HMI 解码。正常 APP
A/B 的 `MonitorTask` 每约 100 ms 尝试发送；当前 B 槽另仅接收独立
无动作诊断 ID `0x220`，其他接收数据帧和全部远程帧均被过滤器拒绝。
没有 CAN 电机控制命令处理、功率级控制或扭矩估算。

| 字节 | 类型 | 内容 |
| --- | --- | --- |
| 0 | `u8` | 协议版本，固定 `1` |
| 1 | `u8` | 电机控制模式：0 空闲、1 位置、2 速度、3 Iq 电流 |
| 2 | `u8` | 位 0 FOC 使能请求；位 1 故障锁存；位 2 编码器数据有效；位 3 `DRIVER_SD` 输出为高。其余位保留为 0 |
| 3–4 | `u16 LE` | `foc_fault_reason` 低 16 位的原始诊断值；不是完整故障分类 |
| 5–6 | `u16 LE` | 成功入队时递增的序号，允许回绕 |
| 7 | `u8` | 保留，固定 0 |

以上标志只是软件状态快照，不证明功率级实际带电、传感器标定合格或设备可启动。
本帧不含扭矩/角度，也不允许 HMI 解除故障或发出运行命令。HMI 校验帧类型、
DLC、版本、保留位和序号；500 ms 没有新合法帧即显示“状态已过期”。

## 已上板的只读测量帧

均为标准 ID、经典 CAN、DLC=8、小端序；每种帧各自有 16 位递增序号，
只有成功入发送队列才推进。无效字段不得显示为零值；HMI 还要求相关帧及
`0x180` 状态帧均在 500 ms 内新鲜，序号有效。

| ID | 字节 0–7 | 说明 |
| --- | --- | --- |
| `0x181` | `angle_mdeg:i32, iq_mA:i16, seq:u16` | 相对机械角；角度无效用 `INT32_MIN`，q 轴电流无效用 `INT16_MIN`。Iq 只有 FOC 正常使能且未故障、未安全锁存时有效。它**不是扭矩**。 |
| `0x182` | `vbus_mV:u16, speed_deci_rpm:i16, seq:u16, valid:u8, version:u8=1` | `valid` 位 0 是母线电压估算有效，位 1 是机械速度有效；无效字段编码为 0。母线估算仅在现有空闲态 ADC2 实时采样有效且年龄 ≤500 ms 时发布。 |

角度为编码器启用后的相对位置，不是绝对工具角；电压是基于启动时 VDDA
估算及分压比 25 的监测值，不是独立校准计量。速度分辨率 0.1 rpm。
`0x183` 扭矩帧仍未实现，因为扭矩传感器/电流-扭矩映射尚未标定。

控制方向新增了默认关闭的拒绝式集成构建，仍未刷写、不能操控电机，见
[`CAN_CONTROL_V0_OFFLINE.md`](CAN_CONTROL_V0_OFFLINE.md)。它不改变当前
FDCAN 拒收及 HMI 只读行为，尤其不能把协议 `START_INTENT` 当成电机启动成功。
另有独立的、构建默认关闭的请求/回执诊断实现，见
[`CAN_SHADOW_DIAG.md`](CAN_SHADOW_DIAG.md)；当前 B 槽显式启用该诊断，
但仍不接受 `0x200` 控制命令，HMI 仍不发送控制帧。

`CAN_STATUS_TELEMETRY=ON` 是正常 APP A/B 的构建选项；
`CAN_LINK_PROBE_ONLY=ON` 时它自动不参与构建，原 SRAM 链路诊断保持独立。
此前 B 槽已完成实物收帧与只读界面验收。
针对后续“鲁班猫 TX 有波形而 STM32 PB9/PB8 无波形”的问题，另有一版
诊断固件：`foc2_app_a/build/can-health/` 和
`foc2_app_b/build/can-health/`。它在现有 `MonitorTask` 中记录 `CAN HEALTH`
串口行，并在总线关闭或发送 FIFO 连续满 2 秒时，最多每隔 5 秒重启
FDCAN 一次、每次启动最多三次；不修改电机控制逻辑，也不开放 CAN 控制指令。
关键字段：`READY=0`/`FAIL` 增长指向初始化失败；`ENQ` 不增长且
`FULL` 增长指向发送队列堵塞；`ENQ` 增长但 `DONE` 不增长表示仅入队，
没有得到控制器的发送完成事件，应同时看 `TEC`、`LEC`、`BO`；
`DONE` 增长表示总线层发送完成，**不证明鲁班猫应用层已解析**。
`EVT_LOST` 非零表示事件 FIFO 溢出，完成计数可能偏低。若三次恢复后
`HALT=1`，固件停止自动重启，避免在故障接线上无限重试。

2026-09-29 已通过 IAP 将首版诊断固件写入 A 槽、回读逐字节验证并试运行，
启动元数据最终为 `CURRENT=A CONFIRMED=A PENDING=-`，随后重新锁存
`ANALOG SAFE LATCHED=1 SD=0 MOE=0 FOC=0`。鲁班猫 `candump` 实收连续的
`0x180`/`0x181`/`0x182` 帧；PB8/PB9 复用寄存器和 FDCAN 发送完成位也与
实际发送一致。首版 `DONE=0` 是对 HAL Tx 事件类型只接受一种取值造成的
**诊断误报**，不是该次收帧失败。源码现已兼容两种表示成功发送的事件；
修正版 A/B 均本地构建通过，**尚未再次刷写**。B 槽仍保留此前可回退镜像。
后续刷写仍应保持电机及机械端
处于安全状态、驱动使能关闭，核对 A/B 分区、回滚镜像和硬件状态，并分别
验证 UART 自检、CAN 帧、超时显示、无 ACK/断线时的行为。注意正常 APP
在进入发送状态帧的 `MonitorTask` 前，需要完成电流采样零点校准；源码
明确要求 PD6010B 的 12 V 采样供电存在。不能把“驱动使能关闭”误解为
断开校准所需的采样供电，也不能为了收到状态帧而绕过校准或安全联锁。

2026-09-28 的上板检查曾发现，原 B 槽程序停在静态电流零点校准失败后的
`Error_Handler`，当时 COM5 不响应；随后硬件/启动问题已排除，
2026-09-29 经 UART IAP 从已确认 A 槽更新 B 槽并自动确认成功。
详见 [`../lubancat_hmi/INTEGRATION_LOG_2026-09-28.md`](../lubancat_hmi/INTEGRATION_LOG_2026-09-28.md)。
