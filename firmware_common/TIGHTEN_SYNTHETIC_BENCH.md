# 板端合成数据测试：它到底验证了什么

这不是让电机去拧螺丝，而是让 STM32 自己运行一个 C++ 的“虚拟电机＋虚拟接头”。
模型消费的角度、速度、电流、扭矩都是这个模型生成的；模型启动前的既有隔离健康检查仍采集真实 ADC 和编码器。
没有扭矩传感器，所以模型数值不能当作真实扭矩。

> 2026-10-08 实机验收未通过：A 槽启动健康检查触发电流保护，合成模型尚未运行。已自动回退原 B 槽并重新锁定输出。详见 `safety_backups/tighten-synthetic-20261008/RESULT.md`。不能把 PC 上 24 场景通过写成板端通过。

## 两套算法分别做什么

`MODE=0` 是现有拧紧流程的**行为镜像**：旋入、判断接触、等待停止、分段电流、保持、结束。
它读取源码里的默认参数，但没有直接调用正在运行的 `TighteningTask`，也不是完整固件在环仿真。

`MODE=1` 是候选算法：接触前减速，通过虚拟扭矩反馈调整虚拟速度，再由 PI 算出虚拟 Iq 指令。
它额外假设“接头位置已知、存在扭矩传感器”，不能直接迁移成你现在的实际电机控制方案。

`PROCESS_OK` 仅表示流程走完。`MODEL_OK` 仅表示模型测量值通过示例判据。
`TRUTH` 用另一个模型真值检查结果；它仍然不是实测值。
尤其是传感器增益偏大 10% 的场景，即使出现 `MODEL_OK`，`TRUTH` 也会为 0。

## 怎么确保不会转电机

- 只能通过 `TightenSyntheticIsolated` 这个 opt-in 构建启用；普通固件默认关闭。
- 编译时必须搭配原有 `FOC_ISOLATED_CONCURRENCY` 硬锁配置。
- SD、MOE、AOE、CCER 关闭。模型运行前，还必须停止内部 TIM1 计数器及原有采样测试。
- 只接受本地串口 `SIM` 命令，不开放 Router/CAN/RPC 模型启动入口。
- 模型模块没有 HAL、GPIO、串口、Flash、真实电机控制或动态堆分配依赖。
- 运行时重新检查隔离、升级、故障和应用忙状态；异常就停止模型，不清除故障。
- 模型运行时拒绝 `BENCH RUN` 和 `FW BEGIN`。
- 私有上下文 4 KiB、结果数组 24 条、静态任务栈 4 KiB；栈不再消耗 FreeRTOS 动态堆。每批最多 128 步，并主动让出 CPU。
- 不自动启动、不自动重复；墙上时钟最多 120 秒。模型的终止指令为零，另有 250 ms 的模型停机尾段。

既有启动健康检查会先进行受限的内部 ADC/编码器/FOC 算术检查，但同样不开放功率输出。
健康确认由原 bootloader/BootHealth 完成，验收脚本不强行确认、不改 bootloader、不清故障。
测试 APP 的最早启动入口屏蔽继承的 SysTick/PendSV，待 `.data/.bss` 和 C++ 静态初始化完成后恢复中断，避免旧 RTOS 状态参与启动。该修复只在本测试构建启用；普通固件入口未改。

原 B 槽是正常固件，不继承测试 APP 的隔离锁。自动回退重启期间必须依靠已经确认的外部电气隔离；串口恢复后验收程序发送关闭输出的 `ANALOG SAFE`。不能据此声称回退启动全过程 SD/MOE 从未开启。

## 合成模型用了哪些假设

示例目标 0.002 N·m、示例误差带 ±5%，不是工业统一标准，也不会写入板端运行参数。
Kt 假设 0.020 N·m/A、惯量 2e-5 kg·m²、电流一阶响应时间常数 1 ms。
接头采用只能向前、不会反向松开的弹簧模型，硬／软刚度分别为 0.20／0.010 N·m/rad。

模型积分步长 0.5 ms、外环决策 1 ms、应用状态机决策 10 ms。
这不等于执行完整 20 kHz FOC、SVPWM、ADC 模拟采样或真实开关模型。
板端 C++ 使用 float32，并关闭了 Python 版本的随机测量噪声和重复试验参数扰动。
现有电流指令限幅 0.40／0.15 A 不变；源码默认旋入 80 rpm 不代表 Flash 内现场当前参数。

未包含真实三相电气模型、反向松脱、回弹、夹紧力、温升、实际时延和真实机械误差。
因此只可以证明代码在 MCU 上按预期运行，不可以证明工业扭矩精度。

## 编译和查看结果

在 A 或 B 工程目录，用 ARM 工具链执行：

```powershell
cmake --preset TightenSyntheticIsolated
cmake --build --preset TightenSyntheticIsolated
```

本地串口采用现有的请求编号格式。以下只适用于已经安装且健康确认的**隔离测试固件**：

```text
70001 FW STATUS
70002 ANALOG SAFE STATUS
70003 BENCH STOP
70004 SIM RUN
70005 SIM STATUS
70006 SIM RESULT 0 1
```

先确认当前槽已健康确认、功率级已电气隔离、`LATCHED=1 SD=0 MOE=0 FOC=0`。
`SIM STATUS` 完成应为 `BUSY=0 DONE=24 PASS=24 FAIL=0 LOCK=1 MODEL=1`。
`SIM RESULT <0..11> <0或1>` 查询某个场景；`SIM STOP` 取消 CPU 模型。
结果里的 `FINAL`、`PEAK`、`TARGET` 单位为 nN·m，除以 1e9 得到模型 N·m。
`MS` 是模型时间，不是任务实际运行时间；任务实际耗时在 `SIM STATUS` 中。

场景编号依次是：硬接头、软接头、未接触、提前卡死、滑牙、扭矩增益偏大 10%、Kt 偏低 20%、40 ms 延迟、反馈中断、故障注入、用户停止、不可达目标。

主机验证：`tests/tighten_synthetic_host` 使用与板端相同的 C++ 核心。
`tools/tighten_synthetic_acceptance.py` 默认只读；执行模型需显式 `--allow-isolated-model`。
它只允许在显式授权模式下运行隔离模型、停止内部采样、在回退后锁定输出；默认观察模式只读。
`--commit-staged` 是独立权限，仅提交已完整暂存的准确镜像。失败也保存 UART 证据，不自动重刷、不清故障。
实际验收报告和保护区核验记录保存在 `safety_backups/tighten-synthetic-20261008`，私有 Flash 备份不要分享。
