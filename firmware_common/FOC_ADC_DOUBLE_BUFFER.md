# ADC 原码双缓冲：现在怎么工作

日期：2026-10-06。这次只改诊断统计，离线验证通过，没有刷写、复位或操作电机。

## 一句话理解

ADC 中断负责“收数据”，后台任务负责“算统计”。电流控制仍在每次 ADC 回调中用最新样本运行，不等后台，也不等一块数据攒满。

每块装 256 对 U/V 原码，共两块。生产者是 ADC ISR，消费者是低优先级 `AdcStats` 任务：

```text
FREE ──ISR开始写──> FILLING ──256对写完──> READY
  ^                                           │
  └────────后台算完并释放── READING <──后台取得─┘
```

例如后台正在读 A 时，ADC 可以写 B。后台处理不过来、A/B 都不可写时，ISR 丢弃下一整块“诊断原码”并计数。它不会等后台、不会覆盖旧块，电流控制仍继续处理本次 ADC 数据。这不是允许丢掉控制采样。

## 这次实际移走了哪些工作

改造前，ISR 每次执行 U/V 的求和、平方和、MIN/MAX、STEP 更新；第 256 点还要复制统计结构并清零下一块。

现在 ISR 只保存两个 16 位原码、记录/比较块元数据、满块时发布 READY。统计计算放在后台；约 20kHz 下一个统计块覆盖约 12.8ms，结果会有诊断延迟，但电流环没有这项块等待。

后台任务使用静态 2048 字节栈，优先级 1，低于 MotorControl(4)、Tightening(3)、Router/Protocol(2)。每轮最多处理两块，然后至少延时一个 tick；没有新增堆分配。正常启动先创建该任务，再启动 ADC；创建失败时关功率级/PWM 并进入错误处理。安全通信启动分支不为此启动采样。

## 为什么不会读到写了一半的数据

- ISR 只有把全部 256 对和元数据写完，才用 release 写 READY。
- 后台用 acquire 取得 READY 后才读数据，并把状态改成 READING。
- ISR 只写 FREE/FILLING 的自有块，READY/READING 绝不覆盖。
- 后台读完才 release 写 FREE，ISR acquire 确认后才能复用。
- 两个状态读之间也可能发生抢占，因此后台会在取得某块 READY 后重新检查另一块，避免漏掉先发布的旧块；块号采用支持回绕的比较。

这个原码队列是 **SPSC（单生产者/单消费者）**，不是 MPSC。不得从第二个 ISR/任务调用 Push，也不得并行启动第二个消费者。适配层还有后台忙保护，并拒绝从 ISR 或关中断状态执行统计计算。

## 怎么看它有没有跟上

沿用项目的请求号协议，例如：

```text
105 ADC BUFFER
106 ADC SPREAD U
107 ADC SPREAD V
108 ADC TIMING
```

- `READY`：有几块完整数据在等后台；不是可写空间数。
- `BUSY`：后台正在处理；不等于发生故障。
- `DONE`：后台累计处理的块数。
- `DROP_B` / `DROP_S`：诊断丢块/丢样本计数。持续增加说明后台吞吐或调度不足，需要检查负载。
- `REJECT`：超过 12 位范围的原码，正常 ADC 数据不应出现。
- `MAX_CYC`：后台统计段观察到的最大周期数，可包含抢占，不是 ISR 的数值；ISR 用 `ADC TIMING` 的 MAX_CYC。
- `STK_VALID=1` 时 `FREE_B`：后台任务已记录的历史最小剩余栈字节，首次上板仍需检查。

`ADC SPREAD` 的 `B` 是采集序号，丢块时会跳号；结果是最近处理完的块。开始阶段 `N=0` 表示还没有结果。U/V 记录必须块号和元数据匹配才可一起分析，MIX=1 不能当作恒定 PWM 的噪声对照。

## 代价和不能夸大的地方

ARM 构建中原码队列 2124 字节，任务栈 2048 字节，TCB 84 字节，任务句柄 4 字节；这些新增静态对象合计 4260 字节，另有诊断字段调整和旧统计对象移除。B 槽新配置总链接 RAM 使用 93328 字节，低侧仅编译配置 93336 字节，均小于现有 131008 字节链接区域；这不代替运行时全系统栈/堆验收。

1. 这是 CPU 读取注入 ADC 原码后的软件双缓冲，不是 ADC DMA、也不是从 ADC 到内存的零拷贝。
2. 块数据不再为后台复制一整块，交接的是所有权；每次样本仍有两次原码存储。
3. 统计移出 ISR 不保证总 CPU 工作量下降；开销移动到后台并增加原码存储和任务调度。
4. 队列生产者没有等待/CAS 重试，但统计结果发布/快照还有短暂关中断。不能把整个 FOC 系统称为无锁或已证明严格实时。
5. 新代码还没有实测 ISR 最大耗时、通信高负载下丢块和运行栈余量；先前 SRAM 测试的约 6.6µs 不能直接沿用。
6. 没有改变 PWM 死区、95% 参考限制、FOC 电压限制或安全关断，没有再次“中断减半”。
