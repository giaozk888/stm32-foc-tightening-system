## 软件继续做了什么

保留四点筛选＋筛选电流两次确认的软件分工，没有恢复诊断构建的原码幅值停机，也没有放宽正常控制版保护。新增：

- `BENCH PROTECTION TIMING`：统计从物理对检查处到筛选／FOC 完成的耗时，包含中断抢占，记录最近值、最大值及达到 50 µs 的次数。达到 50 µs 时锁存计算超时并关断，不能证明这一拍在下个 20 kHz 周期前完成。
- `BENCH PROTECTION FAULT`：保存首次关断后的序号、最近原码、样本时间、最后有效时间、关断时间标记及 SD／BDTR／CCER／CR1。后续故障不覆盖首记录；保护状态仍累积后续报警。
- `BENCH PROTECTION TEST TIMEOUT`：只停止 TIM1 的 ADC 触发，让 TIM7 在没有新 ADC 回调时独立检查并关断。没有直接调用“假超时成功”、没有重启采样，每次启动只允许一次。
- TIM7 额外检查 TIM2 计数实际前进，防止只检查 CEN／配置却遗漏停住的时间基准。
- 离线历史回放工具运行同一个公共 C 筛选和保护核心，不另外用 Python 重写筛选，也不在故障后自动重新初始化。

测试入口只接受本地控制台、非 bootloader 试运行、功率硬关闭、定时器有效、零点已完成且保护无待确认／故障的夹具。它不是电机 START 指令。若有已经触发的 ADC 转换在停止 TIM1 后完成，超时相对那一对最后有效数据计算，不能把测试请求时间冒充最后采样时间。

耗时标记使用 TIM2 的 1 µs 时钟；不覆盖 ADC 中断入口和读取之前的延迟，也不是电气关断波形、最坏耗时证明或控制精度测量。处理器／定时器时钟故障时，时间标记本身也不能被视为可信电气证据。

## 现在还不能直接认定可闭环验收

需要补齐的是三类实物证据，不是更多口头“允许”或给诊断版加一个启动开关：

1. **保护链实物验证**：新 TIM7 检查在完整 FreeRTOS／FOC 并发下正常运行；停采样测试实际锁存并关闭输出；测到执行耗时与真实 SD／PWM 关断时序。
2. **独立硬件保护验证**：驱动板在 MCU 卡住或筛选修补真实脉冲时能自主关断，具有已核对的覆盖范围、阈值、响应和故障反馈。现有软件报警入口不会凭空提供硬件电流检测，也没有为未知驱动故障脚编造接线。
3. **真实功率开关反馈验证**：动力线断开、保护保留的限时桥开关工况下，确认采样时刻、电流换算和反馈质量，再确定修补预算；现有 SD=0 PWM 批次不是功率桥开关批次，且在新预算下失败。

上述证据通过后，才有依据设计保留保护、限时、限速、可立即停止的空载闭环验收版。没有扭矩仪器时不能把空载转速验收扩大为工业拧紧扭矩精度验收。

本轮已发出一次合并问题，询问当前断电／断动力线条件和仅诊断刷写复位许可，并索取独立硬件关断证据。在收到实际状态前不刷板；在保护和开关反馈未确认前不添加带电使能绕过。
