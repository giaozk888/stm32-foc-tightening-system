# 负载分类稳定性和短来源缺口修复（仅仿真）

入口：MATLAB `run_load_repair('full')`，或先 `run_load_repair('smoke')`。正式13场景，每组10个相同种子，旧/新各10次；DOB反馈均OFF，不接入速度、工作Iq上限、补偿增益或FSM调度。不访问硬件，不修改 `firmware_common` 或 A/B 构建默认值。

## 等级与趋势分开

旧分类器冻结在 `native/legacy_phase1/`，C/H保留原字节哈希，MEX仅改入口名称以隔离加载。旧结果目录和完整日志不覆盖。

新分类器继续用原10/25mA等级阈值、5mA迟滞、100ms窗口、30ms等级确认。`load_state` 只输出UNKNOWN/LIGHT/MEDIUM/HIGH。`load_trend_state` 独立输出UNKNOWN/STEADY/RISING/FALLING，所以“重载且仍在上升”同时成立，不会反复用趋势标签替换重载等级。

趋势OLS特征继续记录；另增加100ms趋势滤波、80ms确认和进入阈值一半的退出迟滞，减少短期方向翻转。拒绝点不更新均值、趋势滤波器、驻留或有效信用。短缺口保留旧等级/趋势记忆，但当前两个有效位均为0，不能误作新控制证据。

这些都是软件特征初值，不是物理负载标定值。趋势检测延迟可能增加，报告必须同时保留这个代价、卸载后旧等级保留时间和真实回放的趋势切换次数。

## 短来源缺口：独立仿真适配器

原观察器会对来源无效立即Reset。`native/offline_source_gap.h` 仅在明确的主机编译标志 `DOB_OFFLINE_SOURCE_GAP_FIX` 下接在原monitor前面，未进入MCU编译链。无缺口路径直接调用原monitor，原电流筛选、Id门控、饱和和时序检查不变。

适配规则：

1. 只有观察器此前有效、已取得可信电流基准且没有待确认尖峰/持续Id异常时，才允许进入短来源缺口等待。
2. 已知编码器/时间/非有限值/饱和证据不进入保持，继续原失效路径。STOP、故障或冻结立即失去恢复权限。
3. 最多5ms的间隔包含缺失时间和恢复确认时间。每个缺失点标无效，不调用模型更新、不改Id/Iq LPF、不累计预热或Id持续时间，不重复填充旧样本。
4. 恢复需两个真实、连续、时间戳和序号推进的点；原200mA可信基准距离仍满足，同向且速度变化不超过0.5rad/s。0.5rad/s只是本仿真恢复质量边界，不是新安全阈值。
5. 两个恢复端点仍不产生有效估计或滤波更新。确认后的真实端点重新建立连续性检查基准；随后正常帧只积分自己的1ms，不补算缺失区间。Id持续性在明确的恢复端点断开，不把缺口补作持续异常时间。
6. 超过5ms或恢复不一致，旧估计失效；长缺口只执行一次Reset，后续无效帧保持无效。恢复后仍走原筛选与约398ms预热，不能用旧状态直接恢复有效。

它只是一个待验证的观察器质量策略，不可用来绕过CURRENT_INVALID、硬过流、编码器、控制更新看门狗或任何真实硬件保护。短来源缺口的“无效但保留记忆”不等于“允许电机在坏反馈上继续运行”。

## 对照与审计

`build_load_repair.m` 生成两个模型与独立DLL/MEX实例，避免加载器缓存导致实际比较同一DLL。两个模型都记录新旧分类器，能区分“仅分类改变”与“来源缺口策略改变”。

`load_repair_results/<时间>/` 保存旧/新每次完整gzip CSV、原始输入、独立负载真值、两个分类器、指标、均值/标准差、曲线、源码哈希与运行配置。原始来源缺口用模拟器输入标志注入，不能据此声称实机经常丢失3ms。

```powershell
python -m unittest discover -s tests -p test_dob_source_gap.py
python -m unittest discover -s tests -p test_dob_load_features.py
python -m unittest discover -s tests -p test_dob_load_repair_report.py
python tools/report_dob_load_repair.py simulation/dob_simulink/load_repair_results/<时间>
```

独立审计逐点对照历史基线、控制/物理真值/实际输入，检查保持期无滤波/预热信用、拒绝点无特征/计时污染、单尖峰隔离、原总Iq限幅、NaN/Inf及持续异常。对于没有来源缺口的场景，原33项观察器/控制输出必须完全相同。

统计使用相同10个种子。等级切换、趋势切换分开报告；缺口、复位按评估窗口统计，启动和STOP不混入。真实事件之前已处于“上升中”的标签不能计作0ms成功检测，保留NaN和预先激活标志。延迟增加、漏检或失败检查都应保留，不自动通过改阈值掩盖。
