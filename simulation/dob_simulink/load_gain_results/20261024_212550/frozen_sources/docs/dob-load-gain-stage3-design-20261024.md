# 第3阶段：DOB补偿增益调度，软件候选

本阶段先在独立Simulink副本实现增益调度，不接入MCU、不烧录、不修改正式B、正常A、PI或安全阈值。
第2阶段的速度调度已有一次运行证据，接触保持新分支尚未实机覆盖；晚接触超时和严格jerk数值边界仍存在。
因此本轮主对照将速度调度设为OFF，三组均使用原240 rpm意图和同一原S曲线，单独检验增益出口。

## 接入与审查

三组为DOB OFF、固定gain=0.25、adaptive gain∈[0,0.25]。固定与调度组均保持反馈功能enabled，调度只改变一个无量纲增益，不另加第二份补偿电流。
使用上一已完成的DOB／75 ms分类帧，在同一1 ms控制周期的补偿计算前选gain，再调用原 `DobFeedback_Update`。
补偿沿用独立min(25 mA,5%工作Iq限幅)、0.25 A/s斜率、2/5/20 ms新鲜／保持／失效规则；PI+FF+摩擦+DOB共同经过原±0.50 A限幅和总输出AW。

代码审查发现原主机模型漏掉了MCU已有的 `!(status & DOB_MONITOR_SATURATED)` 新鲜补偿门控。
本轮只在生成的离线副本补齐，三组使用同一副本；观察器仍可在饱和时估计，补偿不刷新并按原时钟保持／衰减。
现有固件和旧仿真文件不改，不把旧主机结果冒充包含了该门控；生成差异保存在 `load_gain_work/reviewed_host_diff.patch`。

## 运行前固定的策略

- 只在RUNDOWN启用自适应增益；RUNDOWN_START、CONTACT_CONFIRM及非SPEED阶段增益为0，原控制和FSM继续拥有输出权。
- 可信分类HIGH且方向归一化均值≥25 mA，或可信RISING且均值≥10 mA，累计30 ms合格证据后请求0.25。
- LIGHT且不RISING累计200 ms合格证据，且已处于加载选择至少300 ms后请求0。
- gain上升1.0/s，下降2.5/s；最大值始终≤0.25。不改PI、Ka、摩擦、DOB估计器带宽或预热。
- 质量需原新鲜DOB条件、SAT128未置位、速度补偿资格≥20 rpm，加上分类有效且年龄≤2 ms。
- 短缺口≤5 ms保持gain且不累计驻留；之后请求0并平滑淡出；200 ms无合格分类后撤销加载选择。没有清空DOB观察器或刷新其有效时间。
- 一次更新跨度>2 ms不做增益追赶，缺失时间不当作合格证据；STOP／故障及非速度阶段不等待斜率，原控制直接接管。
- 正反转使用相同非负gain；真实补偿符号保留原dhat符号，方向归一化均值只供分类。

## 验证计划与判据

14场景：空载、负载阶跃／斜坡／卸载、单尖峰、持续Id异常、来源缺口、噪声、实测噪声回放、反转、早／晚接触、STOP、故障。
每场景三组各10个固定配对种子（1～5/61～65），共420轮。每组外生噪声／负载／机械参数一致；外部真负载不由DOB生成。
关闭Fast Restart，记录植物实际使用的全部5个参数，逐轮核对请求值；实际消费外生输入逐点核对。
复用原C估计器、门控、补偿、S曲线、前馈、摩擦、AW和FSM；电流执行器仍为1 ms一阶假设，不是电气FOC仿真。
主机已有300 rpm额外guard保留；MCU正常500 rpm设置不改变，本模型不用于高转速保护验收。

必须通过：无NaN/Inf、gain范围／斜率、补偿／总Iq限幅、总输出求和、原接触资格、STOP／故障、SAT128不刷新补偿、过期补偿归零、原源码未变、三组实际外生与参数一致。
严格jerk仍使用1000.2 rpm/s²，不调整门槛掩盖原数值边界。
性能按各场景10次均值／样本标准差、配对改善／恶化次数报告，不挑成功轮次或删去异常。
比较速度跟踪MAE、负载后跌速与恢复、卸载超调与恢复、Iq峰值、积分器峰值、限幅时间、无载误补偿及有效率。
预设性能筛选：加载场景MAE不可比固定0.25增加超过5%+0.1 rpm；卸载峰值不可增加>1 rpm、恢复不可延长>50 ms；无载平均绝对补偿不可增加>0.1 mA；接触完成数不可下降。
这些是软件候选筛选标准，不是实机性能或安全阈值。任一关键项不通过就保留为实验候选，不自动移植。

下一出口顺序仍是工作Iq_limit，再到DOB辅助FSM；本轮不同时开放它们，以保留可归因的对照。

## 移植预算

本轮只构建了主机DLL和独立Cortex-M4策略对象，没有生成或烧录新的A/B固件。
ARM `sizeof(LoadGainScheduler)=56 B`；外层开关和cap诊断另8 B。策略对象 `text=708 B, bss=56 B`，未包含完整链接影响，不能直接当作最终固件增量。
上次A链接RAM布局只余40 B、Flash只余664 B；当前实现不能直接叠加，需要先精简调度状态／复用日志并重新链接、预检。

复现：`python tools/prepare_load_gain.py`；MATLAB `run_load_gain('full')`。
独立报告 `tools/report_load_gain.py <结果目录>` 需要numpy/pandas；本机使用Codex bundled Python运行，系统Python3.13没有这两个包。
MATLAB `plot_load_gain('<结果目录>')` 生成标准曲线。报告和绘图均只读取保存的文件。
