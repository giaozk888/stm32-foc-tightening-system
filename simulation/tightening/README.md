# 拧紧软件仿真：先验证逻辑，不冒充扭矩实测

这是一个无硬件依赖的离线工具。没有串口、CAN、SSH、RPC、GPIO 或刷写接口，也不修改
STM32、ESP32、鲁班猫和云端。它用于回答“流程结束是否等于扭矩合格”“延迟与误差会怎样影响结果”。

## 运行

在 `D:\new project` 执行：

```powershell
python simulation/tightening/run.py --repeats 30
python -m unittest discover -s tests -p test_tightening_simulation.py -v
```

## 双倍旋入速度的独立离线配置

```powershell
python simulation/tightening/run.py --speed-profile x2-offline --repeats 30 --output simulation/tightening/results_speed_x2_20261009
```

`x2-offline` 从共享头文件的显式实验分支读取默认 160 rpm、范围 20–240 rpm。
普通配置仍为默认 80 rpm、上限 120 rpm。只翻倍旋入目标和配方上限，不翻倍电流、
电压、接触阈值、后段速度或超速阈值；通用指令上限仍为 250 rpm，超速阈值仍为 300 rpm。
这不是将之前实测的瞬时速度翻倍，也不是读取或修改板端 KVS。

A/B 增加 `RundownSpeedX2Offline` 编译配置，继承硬锁定的合成测试配置；
CMake 拒绝将 `TIGHTEN_SPEED_X2_OFFLINE=ON` 与可运动的普通配置搭配。
该实验编译禁用配方 StorageSave，已有正常 V1 记录仍原值加载、不自动乘二，
防止实验参数影响旧回退固件。`SyntheticTask` 的合成模型取编译期默认值，不取
板端 KVS 配方，因此双倍配置的合成模型目标为 160 rpm，真实电机仍不动作。
原板端合成验收的期望矩阵没有为提速重定义，不能把这个新配置的编译成功称为
原合成验收全部通过，也不能关闭模型过冲保护来凑通过。

本次只进行主机模型、参数模块测试和 A/B 编译，不刷板、不解锁输出、不转电机。
当前电流采样质量问题尚未解决，不能将离线模型结果作为高速带电许可或工业验收。

输出为 `simulation/tightening/results/REPORT.md` 和 `results.json`。JSON 中包含单次场景的
5 ms 曲线、状态转移、全部重复运行、模型参数和输入源码 SHA-256。相同源码与种子可复现。
报告每次生成会覆盖该工具自己的同名结果；若想保留版本，可指定此目录内不同的 `--output` 子目录。

## 原始速度提高三分之一

```powershell
python simulation/tightening/run.py --speed-profile baseline --rundown-rpm 107 --repeats 30 --output simulation/tightening/results_speed_107_20261009
```

80 × 4/3 = 106.67 rpm，按配方的整数单位取整为 107 rpm（实际 +33.75%）。
这是基于原始 80 rpm 的模型覆盖值，不是在 160 rpm 上继续加速。
107 rpm 在原 20–120 rpm 配方范围内，不需要提高上限或更改任何保护阈值。
JSON 分开记录源码默认值、模型有效配方和显式覆盖；STM32 源码、板端 KVS 和固件配置不改。
数值检查通过只表示该模型的离散敏感性满足检查要求，仍须另看硬/软连接和扰动结果，
不能将退出码 0 解释成工业精度、高速实机验收或现场运动许可。

## 哪些来自项目，哪些是假设

从 A/B `main.c` 读取并比较速度 PI、电流指令限幅和停止阈值；从 `tighten_params.h` 读取
18 个参数的范围及默认值。**默认值不是从板端 Flash/KVS 读取的当前值**。
来源不一致或字段结构改变时拒绝静默运行，要求审查镜像逻辑。

基线镜像的应用流程：

1. 旋入：低速检测值＋电流需求持续成立才确认接触；否则超时／行程退出。
2. 接触后等待停止。
3. 依次进入 SEATING、T1、T2、T3、HOLD；各阶段按原配方的电流和时间运行。
4. 后段速度／行程越界则退出；保持时间到达后给出 PROCESS_OK，表示原固件的流程 OK。

这里**没有编译运行 MCU 的 `TighteningTask`**，不能替代原函数测试或固件在环测试。
START 授权、session、RTOS 调度、1 kHz 完整速度估计／斜坡、dq PI、SVPWM 等不在模型内。
源码字符串检查只提示结构漂移，不是形式化等价证明。

## 模型假设

- 电机电流环用一阶响应近似；转矩用 `T_motor = Kt × Iq` 的简化模型。
- Kt=0.020 N·m/A、转动惯量 2e-5 kg·m²、摩擦等均为**合成示例**，未识别你的电机。
- 接触前自由旋入，接触后线性弹簧负载；硬／软模型用不同刚度。
- 明确假定螺纹自锁、只正向运动；不模拟反向卸载、松弛、回差、齿槽转矩或真实夹紧力。
- 电流测量增益／偏置进入简化执行器，扭矩虚拟测量另加增益／偏置／噪声／延迟。
- 角度做 14 位量化；速度用模型转速＋延迟，接触检测用 50 ms 均值，不复现低速速度估计误差。
- 虚拟扭矩传感器测的是模型连接反作用扭矩；真实传感器安装位置／带宽可能不同。
- 模型步长 0.5 ms，控制外环 1 ms，应用状态机 10 ms。**不是完整 20 kHz FOC 仿真**。
- 不模拟母线电压限制、开关尖峰、死区、电源限流、热保护和结构强度。不能据此选择硬件限幅。

工具还会用关闭噪声的场景对比 0.5／0.25／0.05 ms 积分步长，检查数值离散敏感性。
这只验证模型的数值表现，不验证模型是否符合真实硬件；步长等于 50 µs 也不代表执行了实际 FOC。

示例目标 **0.002 N·m、±5%** 只用于比较模型行为，不是工件要求、工业统一精度或板端运行参数。
电流指令限幅仍读自代码：速度阶段 0.40 A、直接电流阶段 0.15 A，不为让模型合格而增加它们。

## 候选方案只存在于仿真

候选控制器假设“已有虚拟扭矩传感器＋已知夹具接触角度窗口”，提前降到低速；接触后由
扭矩误差生成低速参考，再经速度 PI 给出 Iq。扭矩／角度越界、反馈过期、超时或外部故障均退出。
满足虚拟扭矩带和速度稳定窗口才给出 MODEL_OK。它不是生产固件中的已有功能。

这个候选同时改变了接触前速度和反馈方式，比较不是单因素试验。若只有电流而没有实际
扭矩传感器，不能把模型中的虚拟传感器当作真实功能。后续可研究电流扭矩估算，但必须标定。

## 测试与结果解释

覆盖硬连接、软连接、未接触、提前卡死、滑牙模型、传感器增益误差、Kt 变化、延迟、
反馈中断、注入故障、用户停止和不可达目标。重复试验给电机／负载／传感器小幅固定种子扰动。

分清三个结果：

- PROCESS_OK：现有流程走完，不判断 Nm 精度。
- MODEL_OK：候选使用的虚拟反馈认为合格；有测量偏差时仍可能是假合格。
- 真值合格：测试器用控制器不可访问的模型真值，检查最终值与峰值是否落在示例要求内。

程序始终输出 `industrial_accuracy_certified=false` 和 `quality_claim_allowed=false`。
即使所有模型样本通过，也只能证明这些假设与场景下的软件表现，不能证明工业拧紧精度。
正式实机阶段仍缺工件规范、参考扭矩标定、真实负载重复性试验和安全保护验收。

其中 `FEEDBACK_STALE`、非有限数检查和故障注入属于仿真框架的统一保护，不代表现有
固件已经实现同名、同阈值的保护。候选的提前减速依赖假定夹具位置；未知位置提前卡死时
仍可能先发生模型过冲，再被判为异常，因此也不能把拒绝结果当作机械损伤已经避免。
