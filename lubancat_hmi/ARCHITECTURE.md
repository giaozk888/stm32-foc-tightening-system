# LubanCat-2H 工业拧紧上位机设计

## 目标与已验证边界

鲁班猫负责 1024×600 MIPI 触控交互、工单/配方管理、曲线与结果存储、
CAN 通信和后续网络同步。STM32G474 负责 FOC、传感器采样、故障保护和最终
执行决策。CAN 双向基础链路已通过 SRAM 诊断帧验证：STM32 发出的 `0x701`
在 `can0` 收到 10 帧；鲁班猫发出的 `0x321#11223344` 在 STM32 诊断日志中
完整收到。另有 SRAM-only 探针的 `0x180` 状态格式帧被鲁班猫实收。
正式 APP A/B 已加入只读 `0x180`–`0x182` 发送代码；当前 B 槽已刷入并确认，
鲁班猫和 HMI 已验收三类帧持续接收，约每 100 ms 一组。仍不等于产品控制、
扭矩测量及追溯功能完成。

屏幕首版采用板上现有 Qt 5 Widgets 与 SocketCAN，保留旧 MIPI 摄像头项目及
已禁用的旧开机服务。界面进程目前只开 `CAN_RAW` 接收套接字，不发送任何帧。
板上编译与 1024×600 离屏渲染已通过。普通 EGLFS 窗口曾仅亮背光；
现已暂时复用原屏幕项目的 `DrmUiPlane`，DRM 显示状态确认新增 ARGB
界面图层，先前实物显示已由用户确认。CAN 和新版只读 HMI 服务已设为开机自启，
但尚未重启验收；此 DRM 依赖后续应整理为本项目自己的显示后端。

## 软件分层

```text
MIPI/Goodix 触控
      │
Qt HMI：总览 / 作业 / 曲线 / 配方 / 诊断
      │
业务状态机 + 记录服务（待实现；不可由 UI 控件直接操作 CAN）
      │
版本化 CAN 状态解码 + 新鲜度/序号校验（已实现；实时显示已验收）
      │
SocketCAN can0 ─ 收发器 ─ CANH/CANL ─ 收发器 ─ STM32 FDCAN
                                                   │
                                      自检/故障锁存/FOC/传感器
```

未来联网同步与本机控制隔离：网络断开时本机安全保护和已开始的作业不能依赖
云端；网络请求不直通 CAN。持久化使用 SQLite，记录单次作业 ID、配方版本、
设备/固件版本、开始/结束时间、最终结果与曲线块，并以事务提交结果。

## 只读 CAN 状态与测量帧 v1

均为经典 CAN、500 kbit/s、标准 11-bit ID；多字节数值采用小端序。
`0x180`/`0x181`/`0x182` 已在正常 APP B 与 HMI 中实现；B 槽已确认，
三类帧完成实物收帧和界面解码验收。A 槽含同协议代码但尚未更新。
`0x183` 仍只是草案。
**SRAM 探针的故障标记不代表产品状态。**

| ID | 频率 | 8 字节载荷 | 说明 |
| --- | --- | --- | --- |
| `0x180` | 约 10 Hz | `[version:u8=1, mode:u8, flags:u8, fault:u16, seq:u16, reserved:u8]` | 已实现只读状态快照；`fault` 是原始故障原因低 16 位，不是完整分类；细节见 [`../firmware_common/README.md`](../firmware_common/README.md) |
| `0x181` | 约 10 Hz | `[angle_mdeg:i32, iq_mA:i16, seq:u16]` | 相对机械角与 q 轴电流；`INT32_MIN`/`INT16_MIN` 分别表示无效，不推算扭矩 |
| `0x182` | 约 10 Hz | `[vbus_mV:u16, speed_deci_rpm:i16, seq:u16, valid:u8, version:u8=1]` | 母线电压估算与机械速度；`valid` 位 0/1 独立指示有效性，无效字段编码 0 |
| `0x183` | 待标定 | `[torque_mNm:i32, seq:u16, valid:u8, reserved:u8]` | 扭矩只在真实传感器或经验证的电流—扭矩标定完成后启用 |
| `0x701` | 诊断 | `CAN2` + 32-bit 大端序号 | 仅 SRAM 链路测试；上位机不得把它解析为业务状态 |

当前 HMI 在 500 ms 内没有新合法状态帧时显示“状态已过期”，未收到帧时
显示“等待状态帧”；不会把 `can0 UP` 或旧帧显示成“设备在线”。错误帧、
版本不符、DLC 不符及重复/倒退序号不会更新实时值。曲线采样单位和滤波
策略在 STM32、UI、存储导出中应保持一致。

## 作业和控制安全门槛

规划状态为 `SAFE → IDLE → READY → RUNNING → RESULT / FAULT`。在开放触屏
“开始”前，至少需要：可靠的物理急停、母线/温度/电流/编码器自检、功率级
状态回读、配方范围校验、命令唯一序号和限时确认、通信超时行为、掉电恢复
策略、扭矩传感器标定以及无负载/受控负载试验。STM32 必须自主拒绝越界
或过期命令；上位机失联不得解除故障锁存或绕过联锁。

当前运行系统不处理、不发送任何控制帧；界面里的作业与配方按钮保持禁用。
现已在 `firmware_common/CAN_CONTROL_V0_OFFLINE.md` 单独起草并测试
`0x200`/`0x280` 候选控制协议，但未接入固件或 HMI，也没有部署；
缺少真实安全回读和总线可靠性验收之前，仍保持上述只读边界。
“启动前检查”页只比较 `0x180`–`0x182` 的新鲜度、软件状态位、有效位及
同组序号。它不会计算可启动许可，也没有发送控制帧的路径。尤其 `DRIVER_SD`
只是 MCU 输出状态，不是功率级回读；母线值只是估算，软件未报告故障也不
等于物理急停已闭合或 ANALOG SAFE 锁存已解除。页面始终显示“不可启动”，
直至缺失的独立安全反馈、标定与固件控制验收完成后另行设计。
后续分阶段验收：

1. 板上 Qt5 编译、MIPI 显示及 CAN 原始帧只读显示已完成；触控交互需逐页验收。
2. 只读状态与测量帧代码、HMI 解码单元测试、正常 APP B 实物收帧和界面显示已完成；断线与超时的实物测试仍待完成。
3. 最近 30 秒的只读角度/转速内存趋势、手动 SQLite 诊断快照、记录列表和 CSV 导出已实现；仍需扭矩标定、正式过程存档、结果、工单与追溯，以及时间戳和掉电一致性验收。
4. 完成安全联锁、标定和受控环境试验后再设计受限控制帧与配方下发。
5. CAN 与新版只读 HMI 开机自启已配置，仍须隔离条件下做整机重启验收；后续还要做稳定性、权限、升级/回滚和产线验收。
