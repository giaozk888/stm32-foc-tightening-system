# 鲁班猫 HMI ↔ STM32 只读测量链路现场验收（2026-09-29）

## 结论

**只读功能验收通过；总线可靠性与整机重启验收未通过/未完成，不能签完整系统验收。**
本次未试转电机、未发送控制帧、未宣称扭矩或追溯功能合格。

| 项目 | 结果 | 证据与边界 |
| --- | --- | --- |
| STM32 固件身份 | 通过 | UART `FW STATUS`：`CURRENT=B CONFIRMED=B PENDING=- ATTEMPTS=0`。 |
| 当前安全态 | 通过（仅当前运行周期） | `ANALOG SAFE LATCHED=1 SD=0 MOE=0 FOC=0`；`STATUS MODE=IDLE FLT=0`。STM32 下次复位会清除锁存。 |
| CAN/HMI 服务 | 通过 | 两个服务 active 且 enabled；HMI `NRestarts=0`，运行 `build_trend/lubancat_hmi`；`can0` 为 500 kbit/s ERROR-ACTIVE，TX=0、RX 错误/丢包=0。 |
| 实屏与触摸 | 通过 | DRM `video_port1` active，两个 1024×600 帧缓冲；用户现场确认新版总览显示，触摸“曲线”可切换并看到角度/转速趋势。 |
| 解码与趋势软件测试 | 通过 | Windows 和鲁班猫 ARM 上 `status_v1_test`、`measurement_v1_test`、`telemetry_history_test` 各 3/3 通过。趋势只收同序号的新鲜有效帧；超时清空；未标定扭矩不显示。 |
| 60 秒连续帧 | 有条件 | `0x180`、`0x181`、`0x182` 各 600 帧，三者 600 组序号配对，但每种帧均有一次相同的序号跳号：首尾 14559→15159，600 帧应有 601 个序号。跳号原因未定位。 |
| 30 秒复测 | 通过该时段 | 三类帧各 301 帧、各自无跳号；错误帧 0；bus-off 累计值未继续增加。 |
| bus-off 稳定性 | 未通过 | 验收前基线 0，后观察到累计 2；复测时维持 2，当前接口已恢复 ERROR-ACTIVE。仅凭计数不能断定是接线、收发器、控制器还是采集侧导致。 |
| 开机自启 | 配置通过，实机未验收 | HMI/CAN 服务 enabled，服务重启成功；未执行整机重启。鲁班猫重启期间 CAN ACK 可能中断，当前不以重启掩盖 bus-off 证据。 |
| 电机控制、扭矩与追溯 | 未验收 | 电机功率/机械端按用户先前确认保持物理隔离；控制功能禁用，扭矩未标定，趋势只在内存中保存最近 30 秒。 |

## 留存与下一步门槛

- 实时界面图：`measurement-live-2026-09-29.png`；趋势预览：`trend-preview-2026-09-29.png`。
- 保持现有物理隔离和 STM32 安全锁存；不为排查而试转电机。
- 在不改变现场接线的条件下继续观察 bus-off 是否递增；若复现，同步捕获 CANH/CANL 与两侧收发器供电/错误状态，以定位瞬断或位时序问题。
- bus-off 原因确认并修复后，重新做长时连续帧测试；随后在物理隔离条件下单独验收鲁班猫重启自启及 STM32 安全态。
- 急停、功率级回读、扭矩标定、命令超时/拒绝和受控负载试验完成前，不开放上位机“开始/配方下发”。
